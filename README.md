# policybook

**Decision policies you can run, compare, and copy.**

Cache eviction, rate limiting, retry backoff and KV-cache eviction are the same
shape of problem: a small function makes a decision from local state, without
knowing what comes next, and the quality of that rule is the whole game.

Every entry is one policy implemented against a tiny domain interface — in
TypeScript, Python and C — with a one-page explainer that says when *not* to use
it, language-neutral test vectors all three implementations satisfy exactly, and
benchmark numbers generated by this repository rather than quoted from a paper.
Traces are generated from a seed rather than recorded, so a benchmark reproduces
anywhere, down to the float32 bit patterns in the KV-cache domain.

An awesome-list where every entry compiles, has a test, and has a number beside
it.

```bash
npx policybook add cache/sieve          # one self-contained file, no dependency
npx policybook add cache/sieve --lang c # or Python, or C
```

**[Browse and run them →](https://policybook.github.io/policybook/)** · [Tutorial](https://policybook.github.io/policybook/tutorial/) · [Compare KV-cache policies](https://policybook.github.io/policybook/compare/kv-cache/)

## Using a policy

`policybook add` copies one file into your project. It is not a dependency: the
file is self-contained, with any shared helper inlined, and a test copies each
policy into an empty directory and runs it to prove that.

```ts
import Sieve from "./policies/sieve";

const cache = new Sieve<string>({ capacity: 1000 });
// Your storage stays yours; the policy only makes the decision.
cache.onAccess(key, resident.has(key));
if (resident.size > 1000) resident.delete(cache.evict());
```

The same policy in Python and C makes the same decisions on the same inputs —
not approximately, but exactly. That is what the shared vectors are for, and CI
runs all three on every commit.

## What is here

- **`policies/<domain>/<name>/`** — the implementations, README, `policy.json`,
  `vectors.json` and `bench.json` for one policy.
- **`packages/core`** — domain interfaces, trace generators and metrics.
- **`packages/python`**, **`packages/c`** — the ports, and a single-header C
  amalgamation.
- **`packages/cli`** — `policybook add`, `new`, `verify`, `bench`.
- **`apps/web`** — the site: a page per policy with a runner, compare pages, and
  the tutorial.
